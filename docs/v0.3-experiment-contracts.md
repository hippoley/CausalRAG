# v0.3 Experiment Contracts

Experiment Contracts let the causal-agent runtime calculate information value and posterior updates from an explicit observation model instead of asking the LLM to guess them.

## Contract

A contract defines a discrete experiment over mutually exclusive hypotheses:

```python
from causalrag import ExperimentContract, OutcomeLikelihood

contract = ExperimentContract(
    experiment_id="filter_pressure_test",
    description="Pressure drop separates filter restriction from fan weakness.",
    outcomes=[
        OutcomeLikelihood("high",   {"H1": 0.9, "H2": 0.1}),
        OutcomeLikelihood("normal", {"H1": 0.1, "H2": 0.9}),
    ],
)
```

This means the runtime owns the likelihood model:

```text
P(high   | H1, test) = 0.9
P(normal | H1, test) = 0.1
P(high   | H2, test) = 0.1
P(normal | H2, test) = 0.9
```

For every modeled hypothesis, likelihoods across outcomes must sum to 1.

Attach the contract to a capability:

```python
ToolSpec(
    name="measure_filter_pressure",
    description="Measure pressure drop across the filter.",
    handler=measure_filter_pressure,
    metadata={"kind": "observe"},
    experiment_contract=contract,
)
```

The tool result must expose one of the declared outcomes. By default the runtime reads `result["outcome"]`; `outcome_key` can change this.

## Decision-time information value

When every hypothesis referenced by a contract exists in the current `CausalWorldModel`, policy computes:

```text
H(prior) - E_outcome[H(posterior | outcome)]
```

and reports the fractional entropy reduction in `[0, 1]` as `bayesian_information_gain`.

`ActionScore.information_source` then becomes:

```text
runtime_bayesian_eig
```

The current epistemic-source order is:

```text
validated ExperimentContract
    ↓
Bayesian expected information gain

otherwise explicit tests_hypotheses
    ↓
runtime hypothesis-discrimination heuristic

otherwise, when no active hypotheses exist
    ↓
model information estimate fallback
```

Once active competing hypotheses exist, an observation/retrieval/ask action that declares neither `tests_hypotheses` nor an applicable Experiment Contract gets no epistemic utility from its model self-score. The self-score remains in the trace for audit, but it cannot bypass the explicit epistemic state.

This prevents an LLM from defeating runtime policy by saying, for example, `expected_information_gain=100` for an action that is not connected to the uncertainty currently represented by the world model.

## Observation-time update

If an executed capability returns a recognized contract outcome, the runtime applies Bayes directly:

```text
P(H_i | outcome, action)
  ∝
P(outcome | H_i, action) × P(H_i)
```

The posterior is written exactly into the hypothesis state while preserving:

- evidence history;
- hypothesis version;
- supported / active / rejected status;
- transition audit data.

The corresponding transition records:

```text
experiment_id
observed_outcome
posterior
information_gain
information_source
```

A resolved contract observation does **not** also go through the LLM hypothesis updater. This prevents the same evidence from being counted once mathematically and then a second time as an LLM-generated signed weight.

## Applicability boundary

A contract is Bayesian only when its modeled hypothesis set is actually present in the current world model.

If the contract expects `H1` and `H2` but only `H1` exists, the runtime does not invent a prior for `H2` and does not report a Bayesian EIG. Policy falls back to the explicit hypothesis-discrimination layer when possible.

Rejected hypotheses may remain in a contract with zero normalized prior mass, but the whole modeled hypothesis set must exist.

## What is runtime-owned vs proposer-owned

The LLM proposer can see a compact contract summary:

```text
experiment_id
hypothesis IDs
possible outcome labels
description
outcome key
```

It does **not** receive authority to rewrite likelihoods. Likelihoods are capability/runtime configuration.

This keeps the split explicit:

```text
LLM:
  propose hypotheses
  propose candidate actions
  explain why an experiment may matter

Runtime:
  validate capability
  own likelihood model
  calculate EIG
  rank actions
  execute capability
  resolve outcome
  calculate posterior
  persist evidence
```

## Example

Run without an API key:

```bash
pip install -e .
python examples/bayesian_experiment_demo.py
```

The demo deliberately makes the proposer overrate a generic temperature observation and underrate the modeled pressure experiment. Once H1/H2 already exist, the generic model self-score is unanchored and cannot drive epistemic policy. The pressure experiment wins on runtime-owned Bayesian EIG, observes `normal`, and changes the posterior from roughly `0.5 / 0.5` to `0.1 / 0.9`.

## What this is not

Experiment Contracts do not make every CausalRAG action Bayesian.

They require a defensible observation model. When likelihoods are unknown, the system should use the falsification/discrimination layer rather than invent fake precision.

Future work can learn or calibrate likelihood models from repeated experiment history, simulators, domain models, or empirical data. The contract boundary is intended to remain stable while the estimator behind it becomes more sophisticated.
